# 值守 · AI 运维工作台

面向 ERP / OA 业务系统的智能支持工作台。把「受理 → 分诊 → 核对 → 沉淀」这条运维闭环，做成一个可点击的产品原型。

**这个项目要证明的三件事：**
1. 懂业务场景（金蝶账号权限、OA 审批流、经销商订单核对、冻品库存差异）
2. 能把 AI 接进真实流程，且明确人机边界
3. 能独立交付一个完整、精致、可直接演示的前端产品

---

## 快速开始

双击 **`启动演示.cmd`**，浏览器会自动打开 `http://127.0.0.1:5178`。

或者命令行：

```bash
node server.js          # 启动服务
node server.js --open   # 启动并自动打开浏览器
```

需要 Node.js 18 以上（用到内置 fetch）。**没有任何第三方依赖，不需要 npm install。**

---

## 接入真实大模型

编辑 `.env`：

```ini
DEEPSEEK_API_KEY=sk-你的Key
DEEPSEEK_MODEL=deepseek-chat
```

保存后重启服务。左侧栏底部的状态会从「演示答案模式」变成「已连接 deepseek-chat」。

- Key 只留在本地服务进程里，前端通过 `/api/chat` 转发，**不会出现在浏览器**
- 未配置 Key 或网络失败时，自动降级到预置的演示答案，界面不会崩
- 模型可换：任何 OpenAI 兼容接口，改 `DEEPSEEK_BASE` 与 `DEEPSEEK_MODEL` 即可

## 页面与演示入口

| 页面 | 地址 | 说明 |
|---|---|---|
| 总览看板 | `/#dashboard` | KPI、30 天趋势、问题分布、SLA 风险 |
| 智能工单台 | `/#tickets` | 一句话描述问题，AI 输出分诊结论 |
| 数据核对台 | `/#sql` | 中文提问 → SQL → 异常行标注 → 差异说明 |
| 知识库与变更 | `/#knowledge` | 6 篇 SOP + 发布验证时间线 |
| 讲述模式 | `/#story` | 全屏 5 屏，`←` `→` 切换，`Esc` 退出 |

**一键进演示状态**（面试时不用手打，省时间）：

- `http://127.0.0.1:5178/?ask=1` —— 自动填入问题并跑一次 AI 分诊
- `http://127.0.0.1:5178/?run=1` —— 自动跑一次数据核对，直接出 SQL 和异常表
- 加 `&noanim=1` 可关闭所有动效（低配机器投屏用）

**快捷键**：`Ctrl/⌘ + K` 呼出命令面板，可跳页面、搜工单。

## 数据是真的会变的

工单、知识库、变更记录都不是写死的数组。它们走服务端 REST 接口，持久化在 `data/store.json`，刷新、关掉再开都还在。

| 能力 | 入口 |
|---|---|
| 新建工单 | 工单台右上角「新建」，填描述 / 部门 / 优先级 |
| 编辑工单 | 工单条悬浮的铅笔图标，或详情条「编辑」 |
| 状态流转 | 详情条下拉：待处理 → 处理中 → 已解决，每次变更写入操作记录 |
| 删除工单 | 工单条悬浮的垃圾桶图标 |
| 采纳 AI 结论 | 分诊结果底部「采纳并关闭工单」，会真的把状态改成已解决 |
| 沉淀知识 | 分诊结果「沉淀为知识」，真的生成一条知识库条目 |
| 知识库增删 | 「新建条目」/ 卡片右上角删除 |
| 变更记录 | 切到「变更记录」页签，用「记录发布」新增 |
| 重置 | 知识库页「重置数据」，恢复初始 12 条 |

看板上的「待处理工单」会跟着这些操作实时变。

接口一览（详见 `server.js`）：`GET/POST /api/tickets`、`PATCH/DELETE /api/tickets/:id`、`POST /api/reset`、`GET /api/stats`、`GET/POST /api/kb`、`DELETE /api/kb/:id`、`GET/POST /api/changes`。

> 静态部署（GitHub Pages）没有后端时，前端自动降级到浏览器 localStorage，同样能增删改查，只是数据存在各自设备上、彼此不共享。

## 部署到 GitHub Pages

已部署地址：**https://mikasa-52.github.io/anjing-ops-copilot/**

改了代码要重新发布时，一条命令：

```bash
# 需要 classic token，勾选 repo 权限
GITHUB_TOKEN=ghp_xxx node deploy.mjs
```

脚本做四件事：同步 `public/` → `docs/`、用 Git Data API 单次提交、把 Pages 指向 `main /docs`、等待构建并验证链接可访问。

**为什么不用 `git push`**：这套流程是为「`github.com` 不可达、但 `api.github.com` 可用」的网络环境写的，全程走 REST API 提交。空仓库会先用 Contents API 播种一个初始提交，再走 blob / tree / commit 流程。

> Pages 只托管静态文件，AI 会降级为预置答案（左下角显示「静态版 · 演示答案」）。要真实模型能力，请本地运行 `node server.js`。

## 技术选择说明（被问到可以这样答）

- **不用框架**：单文件 HTML/CSS/JS，零依赖、零构建，双击即开，改一行就生效。演示场景要的是稳定，不是工程复杂度。
- **图表手写 SVG**：不引第三方图表库，省掉网络抖动风险，也方便精确控制视觉。
- **AI 走服务端代理**：Key 不进浏览器；前端只发 prompt，拿回结构化 JSON 再渲染。
- **分阶段揭示**：AI 返回结构化结果后，按「分诊结论 → 判断依据 → 处理步骤 → 回复话术」分步呈现，比一次性刷出整段文字更像在思考。
- **降级优先**：无 Key、超时、解析失败，任何一步都有兜底答案，演示永不空屏。
